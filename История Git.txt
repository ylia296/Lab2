ИСТОРИЯ СОЗДАНИЯ СИСТЕМЫ КОНТРОЛЯ ВЕРСИЙ GIT
Git — распределённая система управления версиями, созданная Линусом
Торвальдсом в 2005 году для разработки ядра Linux.
Причины создания:
- необходимость быстрой и надёжной работы с большими проектами;
- поддержка распределённой разработки (каждый разработчик имеет
  полную копию репозитория);
- защита от потери данных и повреждения истории изменений.
Ключевые особенности Git:
1. Распределённая архитектура — у каждого участника есть полная копия
   репозитория с историей изменений.
2. Высокая скорость работы за счёт операций над локальными данными.
3. Ветвление — лёгкое создание и слияние веток проекта.
4. Целостность данных — использование хеш-сумм для контроля изменений.
5. Поддержка нелинейной разработки (несколько параллельных ветвей).
Основные понятия:
- Репозиторий — хранилище файлов проекта и истории их изменений.
- Коммит (commit) — зафиксированное состояние проекта с описанием.
- Ветвь (branch) — независимая линия разработки.
- Слияние (merge) — объединение изменений из разных ветвей.
- Pull request — запрос на интеграцию изменений в выбранную ветвь.
GitHub — крупнейший веб-сервис для хостинга IT-проектов,
основанный на системе контроля версий Git. Позволяет хранить
репозитории в облаке, вести совместную разработку и выполнять
форк (копирование) чужих проектов в собственное рабочее пространство.
Практическая работа № 2. Организация репозитория в системе
управления версиями Git.
